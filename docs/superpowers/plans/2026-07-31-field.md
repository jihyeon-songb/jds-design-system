# Field와 Label 구현 계획

> **에이전트 작업자용:** 이 계획은 `superpowers:subagent-driven-development`(권장) 또는 `superpowers:executing-plans`를 사용해 작업별로 구현한다. 진행 상태는 체크박스(`- [ ]`)로 기록한다.

**목표:** Checkbox를 포함한 control을 조합할 수 있는 `Label`과 `Field` 계열을 `@jds/components`에 추가한다.

**구조:** 모든 컴포넌트는 native `label` 또는 `div` 하나를 forwardRef로 렌더링한다. Field는 배치와 텍스트 구조만 담당하며 control props, `aria-describedby`, invalid 상태를 자동으로 주입하지 않는다.

**기술 스택:** React 19, TypeScript, CSS 사용자 정의 속성, Vitest, Testing Library, Storybook 10

## 공통 제약

- 새 의존성, Context, control 자동 탐색, cloneElement를 추가하지 않는다.
- `Label`, `FieldLabel`은 native `<label>`이고 나머지 Field 컴포넌트는 native `<div>`다.
- `Field`의 `orientation`은 `"vertical" | "horizontal"`만 허용하며 기본값은 `"vertical"`이다.
- label 연결은 `htmlFor`/`id` 또는 label wrapping을 소비자가 명시한다.
- 설명·오류는 소비자가 ID와 `aria-describedby`로 연결하고, `FieldError`는 invalid 상태나 라이브 영역을 강제하지 않는다.
- CSS의 시각 값은 `--jds-*` token만 사용한다.

- [ ] **단계 1: 실패하는 native 구조와 label 연결 테스트 작성**

```tsx
it("connects a native label to Checkbox", async () => {
  const user = userEvent.setup()
  render(<><Checkbox id="terms" /><Label htmlFor="terms">약관 동의</Label></>)
  await user.click(screen.getByText("약관 동의"))
  expect(screen.getByRole("checkbox", { name: "약관 동의" })).toBeChecked()
})

it("renders documented Field slots", () => {
  render(<FieldGroup><Field orientation="horizontal"><Checkbox id="notice" />
    <FieldContent><FieldLabel htmlFor="notice">알림</FieldLabel>
      <FieldDescription id="notice-help">언제든 변경할 수 있습니다.</FieldDescription>
      <FieldError id="notice-error">오류</FieldError>
    </FieldContent>
  </Field></FieldGroup>)
  expect(screen.getByText("알림").tagName).toBe("LABEL")
  expect(screen.getByText("언제든 변경할 수 있습니다.").tagName).toBe("DIV")
  expect(screen.getByText("오류")).not.toHaveAttribute("role", "alert")
  expect(screen.getByText("알림").closest("[data-orientation]")).toHaveAttribute("data-orientation", "horizontal")
})
```

- [ ] **단계 3: 최소 조합 컴포넌트 구현**

`Field.tsx`에 다음 API를 만든다.

```tsx
export type FieldProps = ComponentPropsWithoutRef<"div"> & {
  orientation?: "vertical" | "horizontal"
}

export const Field = forwardRef<HTMLDivElement, FieldProps>(function Field(
  { className, orientation = "vertical", ...props }, ref
) {
  return <div {...props} ref={ref} className={["jds-field", className].filter(Boolean).join(" ")}
    data-orientation={orientation} />
})
```

`Label`, `FieldLabel`은 `<label>`로, `FieldGroup`, `FieldContent`, `FieldTitle`,
`FieldDescription`, `FieldError`는 `<div>`로 구현한다. 모두 ref, native props, className을
전달하고 Field 외의 별도 props는 추가하지 않는다.

- [ ] **단계 3: 필요한 token과 CSS 구현**

`jds.tokens.json`의 `space`에 아래 token을 추가한다.

```json
"field": {
  "group": { "$value": "16px", "$type": "dimension" },
  "item": { "$value": "8px", "$type": "dimension" },
  "content": { "$value": "4px", "$type": "dimension" }
}
```

`Field.css`는 Group의 세로 간격에 `--jds-space-field-group`, Field 내부에
`--jds-space-field-item`, Content 내부에 `--jds-space-field-content`를 사용한다.
horizontal Field만 row, 나머지는 column으로 배치한다. Error는
`--jds-color-field-invalid-border`, Description은 `--jds-color-field-foreground`를 사용한다.
`[data-disabled]` 문맥은 `--jds-opacity-disabled`만 적용하고 control disabled를 바꾸지 않는다.
forced-colors에서는 `forced-color-adjust: auto`를 설정한다.

## 자체 검토

- 명세 적용 범위: 작업 1은 native 구조와 Label 연결, 작업 2는 명시적 설명·오류 연결 및 token layout, 작업 3은 package와 Storybook 검증을 담당한다.
- 의도적인 단순화: Context, control 자동 탐색, cloneElement, validation, 오류 상태 계산, 자동 ARIA 연결을 넣지 않는다.
- 타입 일관성: 모든 작업은 작업 1에서 제공한 `Field`, `Label`, slot 컴포넌트 및 `FieldProps` 계열만 사용한다.
