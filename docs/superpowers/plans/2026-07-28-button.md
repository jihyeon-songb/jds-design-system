# JDSB Button 구현 계획

> **에이전트 작업자용:** 이 계획을 작업 단위로 구현할 때는 `superpowers:subagent-driven-development`(권장) 또는 `superpowers:executing-plans`를 반드시 사용한다. 진행 상태는 체크박스(`- [ ]`)로 기록한다.

**목표:** 접근 가능한 토큰 기반 Button과 이를 배포할 수 있는 `@jdsb/tokens`, `@jdsb/components` 기반을 만든다.

**구조:** pnpm workspace에 토큰 패키지, 컴포넌트 패키지, 배포하지 않는 Storybook 앱을 둔다. 작은 Node 토큰 생성기가 DTCG 원본을 검증하고 CSS 변수·JavaScript 값·TypeScript 타입을 출력한다. Button은 생성된 CSS 변수만 사용하며 하나의 native `<button>`으로 구현한다.

**기술:** pnpm workspaces, TypeScript, React(peer dependency), Node.js, Vitest, Testing Library, Storybook, Storybook accessibility addon.

## 공통 제약

- 패키지 관리는 pnpm만 사용하고 UI 라이브러리나 ThemeProvider는 추가하지 않는다.
- 컴포넌트는 native HTML과 표준 ARIA로 구현하며 Button은 `<button>`만 렌더링한다.
- 컴포넌트 CSS에는 semantic/component CSS 변수만 쓰고 시각 값 리터럴은 쓰지 않는다.
- 공개 props는 명시적 TypeScript 유니온이며 ref와 적용 가능한 native button props를 전달한다.
- variant: `primary`, `secondary`, `outline`, `ghost`, `destructive`.
- size: `sm` 32px, `md` 36px, `lg` 40px, `xl` 44px. `radius.control` 기본값은 8px.
- loading은 `disabled`, `aria-busy="true"`, `data-state="loading"`을 적용하며 일반 상태는 `data-state="idle"`이다.
- 모든 Story에 axe를 실행하고 완료 전 `pnpm typecheck`, `pnpm test`, `pnpm build`, `pnpm lint`를 통과한다.

- `packages/tokens/src/jdsb.tokens.json` — Button용 DTCG 토큰 원본.
- `packages/tokens/scripts/build.mjs` — 토큰·별칭 검증과 배포 산출물 생성.
- `packages/tokens/tests/build.test.ts` — 생성기 검증과 출력 검사.
- `packages/components/src/Button.tsx`, `Button.css` — Button 공개 API와 스타일.
- `packages/components/src/index.ts` — 컴포넌트 패키지 공개 export.

### 작업 2: DTCG Button 토큰과 생성 산출물 만들기

**파일:**

- 생성: `packages/tokens/src/jdsb.tokens.json`, `packages/tokens/scripts/build.mjs`, `packages/tokens/tests/build.test.ts`
- 수정: `packages/tokens/package.json`

**인터페이스:**

- 입력: DTCG group/token 형식의 `jdsb.tokens.json`.
- 출력: `@jdsb/tokens`, `@jdsb/tokens/css`, `TokenName`; CSS 변수에는 `--jdsb-color-action-primary-background`, `--jdsb-size-control-button-md-height`, `--jdsb-radius-control`이 포함된다.

- [ ] **1단계: 실패하는 토큰 생성기 테스트를 작성한다**

임시 DTCG fixture로 정상 별칭 해석, 없는 별칭, 순환 별칭, 중복 flattened 이름을 검증한다.

```ts
expect(() => buildTokens({ color: { a: { $value: "{color.missing}", $type: "color" } } }))
  .toThrow("Unknown token reference: color.missing")

expect(() => buildTokens({ color: { a: { $value: "{color.b}", $type: "color" }, b: { $value: "{color.a}", $type: "color" } } }))
  .toThrow("Circular token reference: color.a")
```

- [ ] **2단계: 테스트가 실패하는지 확인한다**

```sh
pnpm test -- packages/tokens/tests/build.test.ts
```

예상: `buildTokens`가 없어 실패한다.

- [ ] **3단계: 최소 DTCG 생성기를 구현한다**

`$value`와 `$type`을 모두 가진 객체만 token으로 재귀 flatten한다. 둘 중 하나가 없으면 실패시키고, `{path.to.token}` 별칭은 recursion stack으로 순환을 감지한다. path segment를 `-`로 연결해 CSS-safe 이름을 만들고 `--jdsb-` 접두사를 붙인다.

```js
export function buildTokens(source) {
  // { css, source, declarations }를 반환한다.
}
```

생성기는 CSS, `tokens` object가 있는 JavaScript, literal union `TokenName`이 있는 TypeScript 선언만 출력한다. 별도 token runtime abstraction은 만들지 않는다.

- [ ] **4단계: Button 토큰 원본을 정의한다**

primitive → semantic alias → Button-specific 순서로 surfaces/text(5개 variant), focus ring, disabled opacity, control radius, icon gap, 네 가지 height를 만든다.

```json
{
  "size": {
    "control": {
      "button": {
        "sm": { "height": { "$value": "32px", "$type": "dimension" } },
        "md": { "height": { "$value": "36px", "$type": "dimension" } },
        "lg": { "height": { "$value": "40px", "$type": "dimension" } },
        "xl": { "height": { "$value": "44px", "$type": "dimension" } }
      }
    }
  }
}
```

- [ ] **5단계: 토큰을 빌드하고 검사한다**

```sh
pnpm --filter @jdsb/tokens build
pnpm test -- packages/tokens/tests/build.test.ts
```

예상: 통과하며 Button CSS가 쓰는 모든 변수가 생성된다.

- [ ] **6단계: token package를 커밋한다**

```sh
git add packages/tokens
git commit -m "feat: add Button design tokens"
```

### 작업 3: native·토큰 기반 Button 구현하기

**파일:**

- 생성: `packages/components/src/Button.tsx`, `packages/components/src/Button.css`, `packages/components/src/Button.test.tsx`, `packages/components/src/index.ts`
- 수정: `packages/components/package.json`

**인터페이스:**

- 입력: `@jdsb/tokens/css`와 작업 2에서 생성한 `--jdsb-*` 변수.
- 출력: `@jdsb/components`의 `Button`, `ButtonProps`, `ButtonSize`, `ButtonVariant`.

- [ ] **1단계: 실패하는 Button 동작 테스트를 작성한다**

Testing Library와 `userEvent`로 loading의 disabled·접근 가능한 이름·상태, native prop과 ref 전달을 검증한다. 기본 variant/size, start/end icon 순서, native disabled와 loading의 click 차단도 추가한다.

```tsx
it("disables and preserves the accessible name while loading", () => {
  render(<Button loading>Save changes</Button>)
  const button = screen.getByRole("button", { name: "Save changes" })
  expect(button).toBeDisabled()
  expect(button).toHaveAttribute("aria-busy", "true")
  expect(button).toHaveAttribute("data-state", "loading")
})

it("forwards the ref and native button props", () => {
  const ref = createRef<HTMLButtonElement>()
  render(<Button ref={ref} name="save" type="submit">Save</Button>)
  expect(ref.current).toHaveAttribute("name", "save")
  expect(ref.current).toHaveAttribute("type", "submit")
})
```

- [ ] **2단계: Button 테스트가 실패하는지 확인한다**

```sh
pnpm test -- packages/components/src/Button.test.tsx
```

예상: `Button` export가 없어 실패한다.

- [ ] **3단계: Button 공개 API를 최소 구현한다**

`forwardRef` 하나만 사용한다. JDSB props만 분리하고 나머지는 native button에 전달한다. loading은 caller의 disabled보다 우선한다.

```tsx
export const Button = forwardRef<HTMLButtonElement, ButtonProps>(function Button(
  { variant = "primary", size = "md", loading = false, startIcon, endIcon, children, disabled, className, ...props },
  ref
) {
  return (
    <button
      {...props}
      ref={ref}
      className={className}
      disabled={disabled || loading}
      aria-busy={loading || undefined}
      data-state={loading ? "loading" : "idle"}
      data-variant={variant}
      data-size={size}
    >
      {startIcon ? <span aria-hidden="true" data-slot="start-icon">{startIcon}</span> : null}
      <span data-slot="label">{children}</span>
      {endIcon ? <span aria-hidden="true" data-slot="end-icon">{endIcon}</span> : null}
      {loading ? <span aria-hidden="true" data-slot="spinner" /> : null}
    </button>
  )
})
```

loading일 때 CSS는 label/icon을 `display: none`이나 `visibility: hidden`이 아닌 `opacity: 0`으로 숨긴다. 이렇게 하면 accessible name과 버튼 폭이 유지된다. caller `className`은 Button class와 합쳐야 한다.

- [ ] **4단계: 생성 토큰만 쓰는 Button CSS를 구현한다**

component entrypoint에서 Button CSS보다 먼저 `@jdsb/tokens/css`를 import한다. `data-variant`, `data-size`, `data-state` selector를 사용한다. 시각 값 리터럴을 쓰지 않고 모든 선언을 `--jdsb-*` 변수로 만든다.

```css
.jdsb-button:focus-visible {
  outline: var(--jdsb-focus-ring-width) solid var(--jdsb-color-focus-ring);
  outline-offset: var(--jdsb-focus-ring-offset);
}

@media (prefers-reduced-motion: reduce) {
  .jdsb-button [data-slot="spinner"] { animation: none; }
}

@media (forced-colors: active) {
  .jdsb-button { forced-color-adjust: auto; }
}
```

spinner는 semantic border token과 token-backed animation duration으로 만든다. 별도 공개 Spinner 컴포넌트는 만들지 않는다.

- [ ] **5단계: component 테스트와 typecheck를 통과시킨다**

```sh

pnpm --filter @jdsb/components typecheck
```

예상: 통과하며 TypeScript는 `variant="brand"`, `size="xxl"`을 거부한다.

- [ ] **6단계: Button component를 커밋한다**

```sh
git add packages/components
git commit -m "feat: add accessible Button component"
```

## 계획 자체 검토

- 요구사항 적용: 작업 1–2가 workspace와 DTCG 출력을, 작업 3이 승인된 Button API와 상태를, 작업 4가 Storybook·axe·수동 검사·44px 상위 명세 충돌 해소를 담당한다.
- 누락 검사: 불완전한 작업 표시나 정의되지 않은 인터페이스가 없다. IconButton은 승인된 명세대로 명시적으로 제외했다.
- 이름 일치: `ButtonVariant`, `ButtonSize`, `ButtonProps`, `data-state`, package name, token CSS export, 네 size 이름은 Button 설계와 일치한다.
