# Combobox Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 검색 가능한 단일 선택 Combobox를 `@jdsb/components`와 Storybook에 추가한다.

**Architecture:** root context가 선택값, 열림 상태, 검색어, 활성 option을 소유한다. Input은 DOM focus를 유지하고 `aria-activedescendant`로 활성 option을 알린다. Option은 text/ref를 root에 등록하고 root가 필터·키보드·폼 값을 처리한다.

**Tech Stack:** React 18/19, TypeScript, native HTML/ARIA, semantic-token CSS, Vitest + Testing Library, Storybook.

## Global Constraints

- 새 runtime 의존성을 추가하지 않는다.
- native HTML과 표준 ARIA만 사용한다.
- 모든 시각 값은 semantic CSS custom property를 사용한다.
- `ComboboxInput` 소비자는 접근 가능한 이름을 제공한다.
- remote loading, 자유 입력값, 다중 선택, tag, 그룹, virtual scroll, 초성 검색, Portal은 범위 밖이다.
- value와 open의 controlled 상태는 독립적이며 제어된 값은 callback만 요청한다.

### Task 2: 최소 compound Combobox 구현

**Files:**
- Create: `packages/components/src/inputs/Combobox.tsx`
- Modify: `packages/components/src/index.ts`

**Interfaces:**
- Consumes: Task 1의 fixture와 동작 계약.
- Produces: `Combobox`, `ComboboxInput`, `ComboboxList`, `ComboboxOption`, `ComboboxEmpty`와 명시적 props type.

- [ ] **Step 1: root state와 context 타입을 구현한다**

`ComboboxProps`는 root `<div>` props, `children`, `disabled`, `invalid`, `name`, `required`, 그리고 value/open 각각의 controlled-uncontrolled union을 교차한다. context의 option record는 `{ disabled, id, ref, text, value }`다.

```tsx
function requestValue(nextValue: string): void {
  if (value === undefined) setUncontrolledValue(nextValue)
  onValueChange?.(nextValue)
}

const visibleOptions = options.filter((option) =>
  option.text.toLocaleLowerCase().includes(query.toLocaleLowerCase())
)
```

Option은 effect cleanup으로 등록 해제한다. root 밖 part는 `"Combobox compound components must be used within Combobox"` 오류를 던진다.

- [ ] **Step 2: Input, List, Option, Empty를 구현한다**

```tsx
<input
  {...props}
  ref={mergedRef}
  role="combobox"
  aria-activedescendant={activeOptionId}
  aria-autocomplete="list"
  aria-controls={listId}
  aria-expanded={open}
  aria-haspopup="listbox"
  value={query}
  onChange={onInputChange}
  onKeyDown={onInputKeyDown}
/>
```

Input 변경은 query를 갱신하고 open을 요청한다. ArrowUp/ArrowDown/Home/End는 visible enabled option만 활성화한다. Enter는 활성 option 선택·닫기를 요청하고 Escape는 닫은 뒤 query를 선택 option text로 복원한다. List는 닫히면 `null`, 열리면 `role="listbox" id={listId}`다. Option은 `role="option"`, `aria-selected`, `data-state`와 click 선택을 제공한다. Empty는 열린 목록에 visible option이 없을 때만 렌더링한다.

- [ ] **Step 3: form과 root 상태를 연결한다**

```tsx
{name ? <input type="hidden" name={name} value={selectedValue ?? ""} disabled={disabled} /> : null}
```

root는 `jdsb-combobox` class와 `data-state="disabled" | "invalid" | "enabled"`를 제공한다. Input은 disabled/invalid/required와 forwarded ref, 소비자 HTML props를 보존한다.

- [ ] **Step 1: semantic-token stylesheet를 작성한다**

root는 relative, list는 input 아래 absolute full-width, option은 input control 최소 높이를 쓴다. 다음 semantic values만 사용한다.

```css
background: var(--jdsb-color-field-background);
border: var(--jdsb-size-border) solid var(--jdsb-color-field-border);
border-radius: var(--jdsb-radius-control);
min-height: var(--jdsb-size-control-input-md-height);
outline: var(--jdsb-size-focus) solid var(--jdsb-color-focus-ring);
padding-inline: var(--jdsb-space-input-inline);
```

invalid는 `color.field.invalid.border`, disabled는 `opacity.disabled`를 쓴다. Input/Select처럼 forced-colors와 prefers-reduced-motion rule을 포함한다.
