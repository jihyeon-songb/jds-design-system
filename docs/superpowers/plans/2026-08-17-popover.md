# Popover Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Native Popover API를 우선 사용하는 token 기반의 접근 가능한 비모달 Popover compound component를 추가한다.

**Architecture:** `Popover`는 span wrapper와 React context로 controlled/uncontrolled 상태, content ID, trigger/content ref를 공유한다. `PopoverContent`는 native `popover="auto"`와 `toggle` 이벤트를 React 상태에 동기화하고, API가 없는 환경에서는 `hidden`·document Escape·pointerdown fallback만 제공한다. native top-layer 배치는 Trigger의 declarative implicit anchor와 CSS Anchor Positioning으로 제한한다.

**Tech Stack:** React 19, TypeScript, native HTML Popover API, semantic CSS tokens, Vitest, Testing Library, Storybook 10.

## Global Constraints

- 새 런타임·개발 의존성, Portal, focus trap, animation, 위치 계산 엔진을 추가하지 않는다.
- public API는 `Popover`, `PopoverTrigger`, `PopoverContent`, 세 props type과 `PopoverSide`만 export한다.
- `PopoverTrigger`는 native `<button type="button">`이고 `aria-haspopup="dialog"`, `aria-expanded`, `aria-controls`, `popovertarget`를 컴포넌트가 소유한다.
- `PopoverContent`는 `popover="auto"`, stable ID, `data-state`, `data-side`를 노출하고 기본 side는 `bottom`이다.
- Escape 및 바깥 pointer 상호작용은 Trigger와 Content 외부일 때만 닫기를 요청하고, 닫힌 뒤 연결된 enabled Trigger에 포커스를 복귀한다.
- 모든 시각 값은 기존 semantic token만 사용하고 forced-colors에서 시스템 색을 허용한다.

- [ ] **Step 1: state context와 public type을 구현한다.**

`Popover.tsx`에 다음 shape을 작성한다. `assignRef`는 existing Tooltip pattern처럼 consumer ref와 internal ref를 동시에 갱신한다.

```tsx
type PopoverContextValue = {
  contentId: string
  contentRef: RefObject<HTMLDivElement | null>
  open: boolean
  requestOpen: (nextOpen: boolean) => void
  triggerRef: RefObject<HTMLButtonElement | null>
}

const PopoverContext = createContext<PopoverContextValue | null>(null)

function usePopoverContext(): PopoverContextValue {
  const context = useContext(PopoverContext)
  if (!context) throw new Error("Popover compound components must be used within Popover")
  return context
}

export function Popover({ children, className, defaultOpen = false, onOpenChange, open, ...props }: PopoverProps) {
  const [uncontrolledOpen, setUncontrolledOpen] = useState(defaultOpen)
  const contentId = useId()
  const contentRef = useRef<HTMLDivElement>(null)
  const triggerRef = useRef<HTMLButtonElement>(null)
  const isOpen = open ?? uncontrolledOpen
  const requestOpen = (nextOpen: boolean): void => {
    if (open === undefined) setUncontrolledOpen(nextOpen)
    onOpenChange?.(nextOpen)
  }

  return <PopoverContext.Provider value={{ contentId, contentRef, open: isOpen, requestOpen, triggerRef }}><span {...props} className={["jdsb-popover", className].filter(Boolean).join(" ")}>{children}</span></PopoverContext.Provider>
}
```

- [ ] **Step 2: Trigger와 Content lifecycle을 구현한다.**

`PopoverTrigger`는 click consumer handler 뒤 `event.preventDefault()`와 `requestOpen(!open)`을 호출한다. default action을 막아 native 동작이 controlled state보다 먼저 Content를 토글하지 못하게 하되, `popovertarget` attribute는 Trigger와 Content의 implicit anchor association을 유지한다. `PopoverContent`는 `popover="auto"`를 전달하고 API 지원 여부를 `typeof element.showPopover === "function"`으로 확인한다. open effect는 지원 시 `showPopover()` 또는 `hidePopover()`를 호출하고, 미지원 시에만 `hidden={!open}`을 적용한다. effect cleanup에서 `toggle` listener와 fallback document listeners를 해제한다.

```tsx
export const PopoverTrigger = forwardRef<HTMLButtonElement, PopoverTriggerProps>(function PopoverTrigger(
  { className, onClick, ...props }, ref
) {
  const { contentId, open, requestOpen, triggerRef } = usePopoverContext()
  return <button {...props} ref={(element) => { triggerRef.current = element; assignRef(ref, element) }} type="button" className={["jdsb-popover-trigger", className].filter(Boolean).join(" ")} aria-controls={contentId} aria-expanded={open} aria-haspopup="dialog" popoverTarget={contentId} onClick={(event) => { onClick?.(event); if (!event.defaultPrevented) { event.preventDefault(); requestOpen(!open) } }} />
})
```

For fallback close handling, `keydown` must react only to `event.key === "Escape"`; `pointerdown` must return early when `target` is a Node contained by `triggerRef.current` or `contentRef.current`. `requestOpen(false)` must be followed by `triggerRef.current?.focus()` only when it is connected and not disabled. Native `toggle` with `event.newState === "closed"` must issue that same close request and focus restoration. Guard calls with `element.matches(":popover-open")` to avoid invalid duplicate native calls.

- [ ] **Step 1: native Popover API와 fallback의 실패 테스트를 추가한다.**

native API test는 `HTMLElement.prototype`의 원래 descriptor를 저장한 뒤 필요한 method만
최소 mock하고, 각 test 뒤 정확히 복원한다. mock은 native open state를
`data-native-open`으로만 나타내고 production behavior를 구현하지 않는다. Task 1의
fallback test는 native API mock과 분리된 `describe` block에 둔다.

```tsx
const nativeDescriptors = {
  hidePopover: Object.getOwnPropertyDescriptor(HTMLElement.prototype, "hidePopover"),
  showPopover: Object.getOwnPropertyDescriptor(HTMLElement.prototype, "showPopover"),
}
const showPopover = vi.fn(function (this: HTMLElement) { this.setAttribute("data-native-open", "") })
const hidePopover = vi.fn(function (this: HTMLElement) { this.removeAttribute("data-native-open") })

beforeEach(() => {
  Object.defineProperty(HTMLElement.prototype, "showPopover", { configurable: true, value: showPopover })
  Object.defineProperty(HTMLElement.prototype, "hidePopover", { configurable: true, value: hidePopover })
})

afterEach(() => {
  for (const [name, descriptor] of Object.entries(nativeDescriptors)) {
    if (descriptor) Object.defineProperty(HTMLElement.prototype, name, descriptor)
    else delete (HTMLElement.prototype as Record<string, unknown>)[name]
  }
  vi.restoreAllMocks()
})

it("native Popover API와 toggle close를 React state에 동기화한다", () => {
  const onOpenChange = vi.fn()
  render(<Popover defaultOpen onOpenChange={onOpenChange}><PopoverTrigger>설정</PopoverTrigger><PopoverContent>내용</PopoverContent></Popover>)
  const content = screen.getByText("내용")
  expect(showPopover).toHaveBeenCalledOnce()

  fireEvent(content, new ToggleEvent("toggle", { newState: "closed", oldState: "open" }))
  expect(onOpenChange).toHaveBeenCalledWith(false)
  expect(screen.getByRole("button", { name: "설정" })).toHaveFocus()
})

describe("Popover API fallback", () => {
  beforeEach(() => {
    delete (HTMLElement.prototype as Record<string, unknown>).showPopover
    delete (HTMLElement.prototype as Record<string, unknown>).hidePopover
  })

  it("Popover API가 없으면 hidden fallback으로 표시 여부를 관리한다", async () => {
    const user = userEvent.setup()
    render(<Popover><PopoverTrigger>설정</PopoverTrigger><PopoverContent>내용</PopoverContent></Popover>)
    const content = screen.getByText("내용")
    expect(content).toHaveAttribute("hidden")
    await user.click(screen.getByRole("button", { name: "설정" }))
    expect(content).not.toHaveAttribute("hidden")
  })
})
```

`ToggleEvent`가 jsdom에 없으면 `new Event("toggle")`에 `newState`와 `oldState`를 `Object.defineProperties`로 제공한다. fallback test에서는 `showPopover`/`hidePopover`를 prototype에서 delete하고, 첫 render의 `hidden`과 Trigger click 뒤 hidden 제거를 검사한 다음 `vi.restoreAllMocks()`으로 복원한다.
