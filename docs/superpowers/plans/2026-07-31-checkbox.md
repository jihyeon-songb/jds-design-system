# Checkbox 구현 계획

> **에이전트 작업자용:** 이 계획은 `superpowers:subagent-driven-development`(권장) 또는 `superpowers:executing-plans`를 사용해 작업별로 구현한다. 진행 상태는 체크박스(`- [ ]`)로 기록한다.

**목표:** native 동작을 보존하는 접근 가능한 토큰 기반 Checkbox를 `@jds/components`에 추가한다.

**구조:** `Checkbox`는 고정된 `type="checkbox"` native input 하나를 forwardRef로 노출한다. React와 브라우저가 checked 값을 관리하며, Checkbox는 controlled 값을 우선하고 uncontrolled 변경은 `data-state` 갱신에만 기록한다. label·설명·오류 wrapper와 indeterminate 상태는 이 작업에 포함하지 않는다.

**기술 스택:** React 19, TypeScript, CSS 사용자 정의 속성, Vitest, Testing Library, Storybook 10

## 공통 제약

- 새 의존성, 외부 UI·아이콘 라이브러리, custom checkbox role을 추가하지 않는다.
- native `checked`, `defaultChecked`, `name`, `value`, `required`, `onChange`의 동작을 변경하지 않는다.
- `type`은 항상 `checkbox`이며 공개 props에서 제외한다.
- CSS의 시각 값은 기존 `--jds-*` semantic token과 새 `size.control.checkbox` token만 사용한다.
- `data-state` 우선순위는 `disabled`, `invalid`, `checked`, `unchecked`다.
- 새 동작은 먼저 실패하는 컴포넌트 테스트로 명세한다.

```tsx
it("fixes the native type and forwards the ref and form props", () => {
  const ref = createRef<HTMLInputElement>()
  render(<Checkbox ref={ref} name="terms" required value="accepted" aria-label="약관 동의" />)
  expect(ref.current).toHaveAttribute("type", "checkbox")
  expect(ref.current).toHaveAttribute("name", "terms")
  expect(ref.current).toHaveValue("accepted")
  expect(ref.current).toBeRequired()
})

it("updates uncontrolled data-state and preserves a controlled value", async () => {
  const user = userEvent.setup()
  const { rerender } = render(<Checkbox aria-label="약관 동의" defaultChecked />)
  const control = screen.getByRole("checkbox")
  expect(control).toBeChecked()
  expect(control).toHaveAttribute("data-state", "checked")
  await user.click(control)
  expect(control).not.toBeChecked()
  expect(control).toHaveAttribute("data-state", "unchecked")
  rerender(<Checkbox checked={false} onChange={() => undefined} aria-label="약관 동의" />)
  expect(control).not.toBeChecked()
})
```

- [ ] **단계 3: 필요한 토큰 하나와 최소 컴포넌트 구현 추가**

Add this DTCG token beneath `size.control` in `packages/tokens/src/jds.tokens.json`:

```json
"checkbox": { "size": { "$value": "24px", "$type": "dimension" } }
```

Create `Checkbox.tsx` with this component; its change wrapper tracks uncontrolled state only:

```tsx
import { forwardRef, useState, type ComponentPropsWithoutRef } from "react"

export type CheckboxProps = Omit<ComponentPropsWithoutRef<"input">, "type"> & {
  invalid?: boolean
}

export const Checkbox = forwardRef<HTMLInputElement, CheckboxProps>(function Checkbox(
  { "aria-invalid": ariaInvalid, checked, className, defaultChecked, disabled, invalid = false, onChange, ...props }, ref
) {
  const [uncontrolledChecked, setUncontrolledChecked] = useState(Boolean(defaultChecked))
  const isChecked = checked ?? uncontrolledChecked
  const state = disabled ? "disabled" : invalid ? "invalid" : isChecked ? "checked" : "unchecked"

  return <input {...props} ref={ref} checked={checked} defaultChecked={defaultChecked}
    className={["jds-checkbox", className].filter(Boolean).join(" ")}
    disabled={disabled} type="checkbox" aria-invalid={invalid ? true : ariaInvalid}
    data-state={state} onChange={(event) => {
      if (checked === undefined) setUncontrolledChecked(event.target.checked)
      onChange?.(event)
    }} />
})
```

it("keeps native Space-key behavior and excludes disabled values from FormData", async () => {
  const user = userEvent.setup()
  render(<form><Checkbox defaultChecked disabled name="terms" value="accepted" aria-label="약관 동의" /></form>)
  const control = screen.getByRole("checkbox")
  await user.click(control)
  await user.keyboard(" ")

  expect(new FormData(control.form!)).not.toHave("terms")

it("makes invalid ARIA explicit and gives disabled state precedence", () => {
  const { rerender } = render(<Checkbox checked invalid onChange={() => undefined} aria-label="약관 동의" />)
  const control = screen.getByRole("checkbox")
  expect(control).toHaveAttribute("aria-invalid", "true")
  expect(control).toHaveAttribute("data-state", "invalid")
  rerender(<Checkbox checked invalid disabled onChange={() => undefined} aria-label="약관 동의" />)
  expect(control).toHaveAttribute("data-state", "disabled")
})

- [ ] **단계 3: token만 사용하는 native 스타일 구현**

Create `Checkbox.css`:

```css
.jds-checkbox {
  accent-color: var(--jds-color-action-primary-background);
  block-size: var(--jds-size-control-checkbox-size);
  inline-size: var(--jds-size-control-checkbox-size);
}
.jds-checkbox[data-state="invalid"] { outline: var(--jds-size-border) solid var(--jds-color-field-invalid-border); outline-offset: var(--jds-size-border); }
.jds-checkbox[data-state="disabled"] { opacity: var(--jds-opacity-disabled); }
.jds-checkbox:focus-visible { outline: var(--jds-size-focus) solid var(--jds-color-focus-ring); outline-offset: var(--jds-size-focus); }
@media (forced-colors: active) { .jds-checkbox { forced-color-adjust: auto; } }
```

Do not add `appearance: none`, a custom checkmark, transition, or a click handler. The
focus-visible selector deliberately overrides the invalid outline while focus is visible.

## 자체 검토

- 명세 적용 범위: 작업 1–2는 고정 native API, 상태 계약, 폼 동작, token 스타일, 키보드, forced-colors를 다룬다. 작업 3은 패키징, Storybook/axe, 릴리스 검사를 다룬다.
- 의도적인 단순화: custom role, group, indeterminate, label wrapper, 추가 size API는 넣지 않는다. 상위 선택 또는 폼 레이아웃 요구가 생길 때만 추가한다.
- 타입 일관성: 이후 작업은 작업 1의 `Checkbox`, `CheckboxProps` export와 `size.control.checkbox.size`에서 생성되는 정확한 토큰 변수를 사용한다.
