# Dialog Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** native `<dialog>`로 controlled·uncontrolled modal Dialog와 안전한 닫기·포커스 동작을 제공한다.

**Architecture:** DOM wrapper 없는 `Dialog` Context가 open state, refs, generated label IDs를 compound parts에 제공한다. `DialogContent`는 effect에서 `showModal()`/`close()`를 동기화하고 취소되지 않은 Escape·backdrop만 close 요청으로 바꾼다.

**Tech Stack:** React 19, TypeScript, native HTML `<dialog>`, CSS semantic token, Vitest, Testing Library, Storybook 10.

## Global Constraints

- `pnpm`만 사용하며 의존성을 추가하지 않는다.
- native HTML·ARIA와 `<dialog>.showModal()`만 사용한다. Portal, 중첩 Dialog, `method="dialog"`, animation, 별도 focus trap은 제외한다.
- CSS의 색상·간격·크기·테두리·반경은 existing `--jds-*` semantic token만 사용한다.
- WCAG 2.2 AA: keyboard close, visible focus, accessible name/description, Trigger focus 복귀를 검증한다.

- [ ] **Step 3: minimal Context와 components를 구현한다**

```tsx
export type DialogProps = ({ defaultOpen?: boolean; open?: never } | { defaultOpen?: never; open: boolean }) & {
  children: ReactNode
  onOpenChange?: (open: boolean) => void
}

function requestOpen(nextOpen: boolean): void {
  if (open === undefined) setUncontrolledOpen(nextOpen)
  onOpenChange?.(nextOpen)
}

useEffect(() => {
  const dialog = contentRef.current
  if (!dialog) return
  if (isOpen && !dialog.open) dialog.showModal()
  if (!isOpen && dialog.open) {
    dialog.close()
    if (triggerRef.current?.isConnected && !triggerRef.current.disabled) triggerRef.current.focus()
  }
}, [isOpen])
```

Context에는 `open`, `requestOpen`, Trigger/Content refs, generated title/description IDs,
title/description 등록 state를 둔다. Context 밖 part는
`Dialog compound components must be used within Dialog` Error를 던진다. Trigger와 Close는
`type="button"`, handler-first, `preventDefault()` 존중을 사용한다. Trigger에는
`aria-haspopup="dialog"`와 `aria-expanded`를 넣는다. Content는 native `<dialog>`와
`data-state`를 렌더링한다.

`cancel` native listener는 먼저 prevent하고 `onEscapeKeyDown`을 호출한 뒤 취소되지 않으면
`requestOpen(false)`를 호출한다. Content click은 consumer `onClick` 뒤
`target === currentTarget`일 때만 `onInteractOutside`와 close를 실행한다. Title/Description은
mount effect로 generated ID를 등록한다. Content는 title/description 존재에 따라 ARIA
references를 설정하고, title이 없을 때 consumer `aria-label`을 보존한다. open 뒤 focus는
`[autofocus]`, 첫 enabled focusable descendant, Content 순이다.

- [ ] **Step 5: close policy와 a11y regression tests를 추가한다**

```tsx
it("Escape와 backdrop은 취소되지 않을 때만 close를 요청한다", () => {
  const onOpenChange = vi.fn()
  render(<Dialog open onOpenChange={onOpenChange}><DialogContent aria-label="확인" /></Dialog>)
  const dialog = screen.getByRole("dialog")
  fireEvent.cancel(dialog)
  fireEvent.click(dialog)
  expect(onOpenChange).toHaveBeenNthCalledWith(1, false)
  expect(onOpenChange).toHaveBeenNthCalledWith(2, false)
})

it("title/description을 연결하고 close 뒤 Trigger로 복귀한다", async () => {
  const user = userEvent.setup()
  render(<Dialog><DialogTrigger>열기</DialogTrigger><DialogContent><DialogTitle>제목</DialogTitle><DialogDescription>설명</DialogDescription><DialogClose aria-label="닫기">×</DialogClose></DialogContent></Dialog>)
  const trigger = screen.getByRole("button", { name: "열기" })
  await user.click(trigger)
  expect(screen.getByRole("dialog", { name: "제목" })).toHaveAttribute("aria-describedby", screen.getByText("설명").id)
  await user.click(screen.getByRole("button", { name: "닫기" }))
  expect(trigger).toHaveFocus()
})
```

추가 cases: controlled Dialog은 false만 요청, Escape/backdrop/Trigger/Close handler의
`preventDefault`, Content 내부 click, aria-label only Content, autofocus priority, disabled/removed
Trigger focus skip, ref/native props forwarding, public exports와 invalid compound context.
