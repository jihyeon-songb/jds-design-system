# Toast Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 하단 가운데에서 최대 세 개의 상태 알림을 관리하는 접근 가능한 ToastProvider와 useToast API를 제공한다.

**Architecture:** `ToastProvider`가 Context에서 Toast 목록과 timeout을 소유하고, `useToast()`가 variant별 추가 및 ID 기반 dismiss API를 반환한다. Provider가 viewport와 `Toast`를 직접 렌더링하므로 Portal이나 별도 상태 라이브러리가 필요 없다.

**Tech Stack:** React 19, TypeScript, CSS semantic token, Vitest, Testing Library, Storybook 10.

## Global Constraints

- `pnpm`만 사용하며 runtime dependency와 token을 추가하지 않는다.
- `ToastProvider`, `useToast`, `Toast`와 명세에 정의한 named type만 export한다.
- 위치는 화면 하단 가운데로 고정하며 Portal, 위치 prop, action, title, icon, animation, Promise helper를 추가하지 않는다.
- success·info·warning은 5초 후 닫고 error는 자동으로 닫지 않는다.
- 최대 세 개다. 초과 시 가장 오래된 non-error Toast를 제거하며 error 세 개이면 새 알림은 `undefined`를 반환한다.
- CSS의 시각 값은 existing `--jdsb-*` semantic token만 사용한다.
- 모든 Toast는 `role="status"`와 `aria-live="polite"`를 사용하고 focus를 이동시키지 않는다. 닫기는 `type="button"`, `aria-label="닫기"`, visible focus를 가진다.
- timer ID는 `useRef`로 관리하고 불필요한 `useMemo`/`useCallback`을 추가하지 않는다.

- [ ] **Step 3: 최소 Context, lifecycle과 Toast implementation을 작성한다**

```tsx
const AUTO_DISMISS_MS = 5_000
const MAX_TOASTS = 3

export type ToastVariant = "success" | "info" | "warning" | "error"
export type ToastOptions = { message: ReactNode; variant?: ToastVariant }
type ToastRecord = Required<ToastOptions> & { id: string }

const ToastContext = createContext<ToastApi | null>(null)

export function useToast(): ToastApi {
  const context = useContext(ToastContext)
  if (!context) throw new Error("useToast must be used within ToastProvider")
  return context
}
```

`Toast`는 forwarded `<div>`로 `message`, `onDismiss`, `variant`를 받고 `role="status"`, `aria-live="polite"`, `data-variant`, close button을 렌더링한다. Provider는 consumer props/ref를 받는 일반 wrapper와 별도의 `<div role="region" aria-label="알림">` viewport를 렌더링한다. viewport만 fixed positioning을 받아 children layout을 바꾸지 않는다.

Provider는 records와 `Map<string, ReturnType<typeof setTimeout>>` ref를 소유한다. `replaceRecords(next)`는 `recordsRef.current = next`와 `setRecords(next)`를 함께 수행한다. success/info/warning 추가 후 5초 timer를 등록하고, `dismiss(id)`는 `recordsRef.current.filter(...)`를 `replaceRecords`에 넘기며 timer도 clear한다. effect cleanup에서 남은 timer를 모두 clear한다.

`add`는 `recordsRef.current`을 한 번 읽어 capacity를 동기적으로 판정한다. 여유가 있으면 새 record를 추가한다. 가득 찼으면 `findIndex((record) => record.variant !== "error")`로 가장 오래된 non-error를 찾고, 그 record의 timer를 clear한 뒤 제거하고 새 record를 추가한다. 찾지 못하면 state를 바꾸지 않고 `undefined`를 반환한다. 이 shared ref 방식으로 연속 add 호출에서도 반환 ID와 렌더 목록이 같은 순서를 따른다.
